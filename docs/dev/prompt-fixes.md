# Prompt fixes behind switches

The audit's prompt fixes (docs/plans/audit-2026-10-01.md, "Prompts: what to change") and two engine-review items, each behind its own switch in `config/app.config.json` → `promptFixes`. All switches ship **off**. With every switch off the prompts, request bodies, repairs and specs are byte-identical to before (test: `packages/engine/test/prompt-fixes.test.ts` holds the sha256 of every prompt as it was on main; a `pnpm eval --replay` gives the same request hashes as main).

They change model output, so each one is measured by a paid eval before it is turned on for good: turn one on for a run with `--prompt-fixes <name>` and run the fixtures named below (`--record-missing` pays only for the calls the fix changes).

| Switch | What changes | Where | Measure with |
|---|---|---|---|
| `pictures` | Brief `imageIdeas`: the client's own materials, tools and products where they are used, in ordinary Slovenian surroundings; landscape only when the business sells the place; no people or body parts; first idea is the hero (wider scene, subject in the middle third); a good and a bad example. Generated pictures get `imageGen.pipeline.unstagedStyle` (unstaged smartphone photo, signs of use, no people or body parts, no text) instead of `style`. | `briefSystem`, `pipelineStyle` | `--scope home --judge` on instalacije-rebernik, racunovodstvo-seliskar, fizioterapija-pregib; look at the pictures |
| `critique` | Priorities (a repeated action or fact on a screen; a type-only hero although a hero-suitable photo exists, with the ids passed in; trade/town-only eyebrows; first person, one number, no dual, no English); Slovene changed only for clear errors; component failures go to issues and never cause deletions; the unseeable checklist items (body text size, LCP preload) dropped; JSON only with an op example. | `critiqueSystem`, `critique()` | `--only gostilna-zlata-zlica`, `--only avtoservis-mrak` |
| `altText` | The business type and the owner's description (≤ 1,500 characters) go with the photos; `heroSuitable` has criteria (sharp, well lit, survives 4:3 and square crops, shows the place, work or products; false for logos, documents, dark or cluttered shots). The "placeholder with a caption" leftover is gone. | `altSystem`, `altTexts(…, context)` | any fixture with photos; compare `heroSuitable` and alt texts |
| `judge` | Eval only. Required placeholders and the phone bar are intended, not faults; generated pictures are counted in the context; the direction name is only a reference; notes come before scores in the schema. | `tools/eval/src/judge.ts` | the next `--judge` run (judge scores move, compare with the review sheets) |
| `brief` | The brief no longer carries the site's RULES (~600 tokens it doesn't use); it gets two rules of its own (never invent facts; Slovene text, English picture subjects) and the address rule ("Glavni trg 9, 8000 Novo mesto" → street, postal code, town). | `briefSystem` | `--only fizioterapija-pregib` (its brief returned `address: null`) |
| `classifier` | What confidence means: 0.8–1 clear, 0.5–0.8 rough fit, ≤ 0.5 a business no type fits, 0–0.2 not a business. Ties into the junk threshold (`tiers.junk.minClassifierConfidence` 0.12): recalibrate with `pnpm eval:junk` before keeping it. | `classifySystem` | `pnpm eval:junk` (paid) |
| `edit` | The cached edit block lists the editor's Slovene section names ("Poziv k dejanju" = cta …, from `SECTION_LABEL`); the reply is in the request's language. | `editSystem` | the fixtures' scripted edits (`--record-missing`, edits only change) |
| `directions` | Industrial and soft-studio no longer promise black-and-white or duotone photos (photos keep their colour since PR #23); `Imagery:` says what the treatment does ("square-cut photos in their true colours") instead of `monochrome`/`duotone`; editorial's homepage heroes are hero-type:large and hero-split:image-right (it offered page-header:plain and no photo hero); the design prompt's "Avoid" list is gone (tokens and `enforceDesign` enforce it). | `directionsCatalogue`, `designSystem`, `directionHeroes` (content message) | `--only avtoservis-mrak` (industrial), `--only frizerstvo-lana` (soft-studio), an editorial fixture with photos |
| `warmSurface` | Warm directions (`WARM_SURFACE_DIRECTIONS`: warm-craft, skorja, etiketa, jedilnik) may take a warm non-cream surface (`isWarmTint`: hue 8–30°, saturation ≥ 0.45, lightness 0.82–0.92: peach, apricot, terracotta-tinted). Repair turns their cream surface into such a tint (`toWarmTint`) instead of the cool fallback; the edit prompt says so. `checkDesign` accepts the tint on those directions whatever the switch says, so a site made with it stays valid when it is off. | `enforceDesign(…, { warmSurface })`, `editSystem` | pekarna-kvas "Toplejše barve, kot skorja kruha" |
| `oneHero` | Exactly one main heading (hero, page-header, legal, 404, or a collection list opening its page) per page, first. Checked after content generation (the model retries) and after critique and chat-edit patches (only problems on pages that had none before block). Safe repairs in code: a page's only heading moved down goes back to the top; a standard page without one gets a plain page-header titled with its nav label. Not part of `validateSite`. | `mainHeadingIssues`, `repairMainHeadings` (`packages/spec/src/headings.ts`) | `--only` 2–3 fixtures; all 10 goldens already pass |
| `beige` | Repair of generated and model-edited designs treats a light warm beige page background (`isBeige`: lightness 0.78–0.88, hue 20–75°, not grey; #ece3d0, #e8d5b7) as cream and replaces it. `checkDesign` is unchanged (existing sites stay valid); owner edits in the editor are not repaired by it. | `isCreamOrOffWhite(…, { beige })`, `enforceDesign(…, { beige })` | design tests; any eval |
| `catalogue` | Hero eyebrow: optional, usually left out, never just the trade or town. Contact strip: no longer "right after the hero". Cta: only for an action not offered yet, never to repeat call/directions. RULES: "Mobile first" becomes responsive (desktop and phone both excellent) plus one primary action per screen and at most one call button on a page besides the header and phone bar; placeholders only for facts a section can't do without. | `sectionCatalogue`, `rules` (content, critique, edit, brief) | `--only avtoservis-mrak,frizerstvo-lana,instalacije-rebernik --judge`; the variety report's skeleton and copy numbers |

How the switches reach the code: stages read `client.promptFixes` (the `ModelClient`'s config); `applyPatches` takes them as a fourth argument (the pipeline passes `config.promptFixes` for the critique); the eval CLI's `--prompt-fixes all|<names>` sets them for one run. The wording lives in `packages/engine/src/prompt-fixes.ts`; each fix swaps an exact old passage and throws when that passage is gone, so a later edit to the old wording can't turn a fix into a silent no-op.

The eval's variety report has a copy overlap section (`tools/eval/src/copy-similarity.ts`): the word overlap of each homepage's hero headline, eyebrows and section titles across trades and within a trade (twins), the business's own name and town left out, and the headings several homepages share word for word. Free, from the spec.
