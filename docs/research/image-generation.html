Image generation plan

How we get real images (not only icons) from an image model, how Claude Code drives it for you, and where generated images may and may not appear on a client's site.

29. 9. 2026 Status: proposal, nothing built Branch claude/image-generation-integration-896eb6

Short answer

  1. Connect Claude Code to fal.ai's hosted MCP server. Claude can't make photos, but one fal key reaches the strongest image models (OpenAI, Google, FLUX, Recraft, Seedream, Ideogram). Prepaid credit is a hard spending cap. Claude writes the prompt, runs the model, downloads the image into the repo and opens it to check before keeping it.
  2. Icons need no model. Use the Lucide set (ISC licence) as inline SVG: consistent, a few hundred bytes each, and zero cost.
  3. First job: realistic fixture photos. Run a 30-image comparison of three models, then replace the 36 SVG colour-field stand-ins with the winner's photos and re-record the evals. €5.50–7.80 in total.
  4. On client sites, keep "client photos only" for now. Add a shot list that tells owners which photos to take, and upscale-only edits of their own photos. Since 2. 8. 2026 a photoreal generated image on a business's site probably needs a visible AI label (EU AI Act, Art. 50). A picture that looks like the business can still mislead customers even with the label.
  5. What only you can do: create the fal.ai account, add prepaid credit, and create an API key. I can't create accounts or enter payment details. Four more choices are in Decisions for you.

Why the rule is "does it claim to show the business"

A visitor reads every photo on a bakery's site as that bakery's bread. A generated loaf is then an invented fact, the same as an invented opening hour, and CLAUDE.md already forbids those.

Even a photoreal detail shot (flour, a stone wall) on a business's site probably counts as a deep fake under the AI Act guidelines, so it needs a visible label. Stylised illustration avoids that. See Law and licences.

What Claude can do on its own

Can

  • Write SVG by hand: icons, simple marks, patterns, diagrams, placeholder frames.
  • Look at images. Claude Code's Read tool opens PNG and JPG files, so after an image model returns a file, Claude checks it (wrong hands, text glitches, off-brief) and retries with a better prompt.
  • Write the prompts. A good image prompt is mostly art direction, which Claude does well.

Can't

  • Output pixels. No Anthropic model generates raster images, so photographs need a second model from another company.
  • Hand-drawn SVG "photos" look like clip art. Fine for icons, not for a hero image.

So the setup is: Claude Code is the art director, an image model is the camera, and an MCP server is the cable between them. Claude writes the prompt, calls the model through MCP, saves the file into the repo, opens it to check, and iterates.

Setting up fal.ai

  1. You: create an account at fal.ai, add prepaid credit ($10 covers everything planned on this page), and create an API key.

  2. You: save the key as a Windows user environment variable named FAL_KEY (Settings → System → About → Advanced system settings → Environment Variables, which keeps it out of shell history). Restart the Claude app so it sees the variable.

  3. Me, in a small PR: add .mcp.json to the repo. Claude Code fills in ${FAL_KEY} from your environment, so no secret goes into git, and every worktree gets the server. Claude Code asks you once to approve it.

    {
  "mcpServers": {
    "fal-ai": {
      "type": "http",
      "url": "https://mcp.fal.ai/mcp",
      "headers": { "Authorization": "Bearer ${FAL_KEY}" }
    }
  }
}

    Or, for your account only, in PowerShell (this stores the key in ~/.claude.json):

    claude mcp add --scope user --transport http fal-ai https://mcp.fal.ai/mcp --header "Authorization: Bearer $env:FAL_KEY"

What Claude Code then does per image

  1. Checks the current price with fal's get_pricing and states the total before starting.

  2. Writes the prompt from the brief, for example the subject of each fixture photo in brief.json.

  3. Runs the model, downloads the result into the repo, and opens it to look for wrong hands, garbled text, or a picture that misses the brief.

  4. Keeps it or retries with a better prompt, and records model, prompt and cost in a manifest next to the images.

  5. Stops at the budget you set. The prepaid credit is the hard limit.

In the product pipeline

Claude Code with MCP is for us, at development time. Client sites need the same model called from the worker, through our own code, so it follows the engineering rules in CLAUDE.md. Sketch only; nothing here is built.

  1. One adapter, provider chosen in config

    packages/engine/src/imagegen/ with generate(prompt, aspect, size) and edit(image, instruction, aspect). Each returns bytes, size, model id and cost. The provider, model id, size and quality live in config/app.config.json next to the Claude models; per-image prices go in a pricesUsdPerImage table.

  2. Spec v2: every image knows where it came from

    ImageAsset gains origin: "client" | "edited" | "generated" and, for the last two, the model, prompt and source image. The v1 → v2 migration sets origin: "client" on every existing image, with a test. Validation rejects a non-client image in slots that show the business (team, gallery, services, about).

  3. Marked in the file and on the page

    Our sharp step re-encodes every image and drops metadata by default, so any C2PA or IPTC marking the provider embedded is lost. We write it back: the IPTC DigitalSourceType as XMP via sharp's withXmp() (0.34.3+). sharp documents XMP output for WebP, JPEG and PNG but not AVIF, so the AVIF variant needs a test or a different writer. Generated images also get a visible Slovene label where the rules below require one.

  4. Cost logged and capped like every model call

    Stages image.generate and image.edit log count and € per call and count toward dailyModelSpendCapEur. A per-site limit (limits.maxGeneratedImages) keeps one intake from generating dozens.

  5. Tests without the network

    Unit tests replay recorded responses (small PNGs plus JSON) with the network blocked, as the Claude calls do today. Only pnpm eval calls the real image API. New eval checks: no generated image in a business slot, label present, file weight within the LCP budget.

  6. Client photos are personal data

    Sending an owner's photo (faces, staff, customers) to an editing API makes that provider a sub-processor. Prefer an EU processing region, sign its data processing terms, and name it in the privacy-policy template.

Law and licences

Research, not legal advice. The EU rules changed this summer, and they decide how far client-facing generation can go.

EU AI Act, Article 50: in force since 2. 8. 2026

  • We are likely both provider and deployer. A product that generates images under its own name is a provider and must mark outputs in a machine-readable, detectable way. Because we choose what gets published, we are also a deployer, and so is the client. No passage covers website builders specifically.
  • A photoreal loaf on a bakery site probably counts as a deep fake. The Commission's July guidelines include objects, consumer goods, buildings and places that plausibly exist, even invented ones, and need no intent to deceive. Deep fakes need a visible disclosure; the provider's hidden watermark doesn't count.
  • Stylised illustration probably doesn't. Icon-scale graphics are outside the marking duty.
  • Upscaling and relighting can fall under the exception for standard editing that doesn't substantially alter the input (my reading). Extending a photo adds invented content, so treat that as generated.
  • No grace period for us. The Digital Omnibus (Regulation 2026/1744) gives only systems already on the market before 2. 8. 2026 until 2. 12. 2026 for marking. Fines reach €15 m or 3 % of turnover, the lower of the two for SMEs.
  • Code of Practice (final 10. 6. 2026, voluntary, ~190 signatories): for images, signed metadata plus an invisible watermark, and the EU "AI" icon for deployers.

Misleading customers, copyright, provider terms

  • A label doesn't cure a misleading picture. Under the Unfair Commercial Practices Directive (Art. 6) and Slovenia's ZVPot-1 (Art. 47–49), the overall impression counts. An AI image that looks like the shop, the staff or the product is the highest-risk case, and liability can reach whoever acts on the trader's behalf.
  • Nobody may own a prompt-only image. ZASP needs a human author, and EU courts have leaned that way. Don't promise clients exclusivity or copyright.
  • Our pipeline strips the provider's marks. sharp drops metadata, and any re-encode breaks a C2PA signature. Black Forest Labs' EU terms forbid removing Content Credentials. We must write our own marking and test whether the invisible watermark survives AVIF at quality 55.
  • Output ownership: OpenAI, Google and Black Forest Labs leave the output to the customer. Recraft's free plan keeps ownership and bans commercial use. Indemnities: Google's covers GA models on Vertex AI; Adobe's needs an enterprise contract; Black Forest Labs has none.
  • Stock photos aren't the client's either. Unsplash's API requires hotlinking and credit; Pexels allows commercial use. Same misleading-picture risk.
  • Icon sets are clear: Lucide (ISC), Tabler, Phosphor, Heroicons (MIT), Material Symbols (Apache 2.0). Ship a third-party licences file with the export.

Rules I'd add to PRODUCT.md if generation reaches client sites

  1. Never generate the business: people, staff, premises, finished work, or its own products and food. Enforced by the spec, not by the prompt.
  2. Development and eval use is unrestricted. Fixtures are fiction and never reach the public.
  3. Client-facing generation stays off until you decide. If on: stylised illustration by default; any photoreal image carries a visible Slovene label and the EU AI icon, rendered by the component so the client can't remove it and preview equals published.
  4. Upscale and relight count as edits. Extending or removing content counts as generated.
  5. Every image records its origin, model and prompt in the spec; generated files get IPTC DigitalSourceType written back after sharp.
  6. Providers must mark outputs (C2PA plus watermark) and grant commercial rights on the plan we pay for.
  7. Publishing is blocked when a generated image lacks its label or sits in a slot that shows the business.
  8. A Slovenian lawyer reviews our provider/deployer position before client-facing generation launches.

Decisions for you

Each has my recommendation first. The first is needed before anything else can start; the other three can wait until the comparison images are in.

Which image service Claude Code connects to

  • Recommendedfal.ai: one key, every strong model, prepaid credit as the cap.
  • OptionBlack Forest Labs: sign-in instead of a key, FLUX.2 only, trains on what you send.
  • OptionHugging Face: free, 5 GPU-minutes a day, weaker images.
  • Optionmcp-image with a Gemini key: direct Google prices, community-maintained.

fal lets us compare OpenAI, Google and FLUX on our own fixtures before committing to one vendor for the product.

Generated images on client sites

  • RecommendedKeep "client photos only", and add the shot list and upscale-only edits.
  • OptionAllow stylised illustrations that the owner opts into, never in slots that show the business.
  • OptionAllow photoreal mood images with a visible AI label.

Photoreal images on a business's site probably need an AI label since August and can still mislead customers. "Your real business, no stock" is also part of what sets the product apart. Revisit after a lawyer's view and the comparison images.

Edits to the client's own photos

  • RecommendedUpscale and relight only, with the original kept and the owner approving.
  • OptionAlso extend and remove objects, marked as AI-edited.
  • OptionNo edits; sharp crops as today.

Upscaling fixes the most common problem (small phone photos) and likely falls under the standard-editing exception. Extending adds invented content and brings the labelling duty with it.

Where the fixture photos live

  • RecommendedCommit them as JPEGs at 1600 px (roughly 5–10 MB for all 36).
  • OptionGenerate on demand, not committed, as today.
  • OptionKeep them in the Railway bucket and download on setup.

Eval recordings depend on the exact photos. Committed files keep evals repeatable and offline, and each regeneration would cost money and change the results.
